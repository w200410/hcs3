SYSTEM INTEGRATION · CASE 03

大型餐飲服務集團

跨系統資料同步與交換自動化

建立中介資料庫作為多套異質系統的共通交換層，讓資料介接從一次性程式，轉變為可排程、可追蹤、可復原並能持續延伸的整合架構。

本案例整理自核心成員過往任職期間主導的企業系統專案經驗，為保護客戶及合作夥伴資訊，採匿名方式呈現。

01 · PROJECT BACKGROUND

系統持續增加，Excel 成為系統之間的搬運工具

隨著企業資訊化範圍逐步擴大，既有人資系統先後產生與 ERP 基礎資料、電子簽核系統、會計傳票、人才發展系統及 BI 分析系統進行資料交換的需求。

在系統介接完成前，不同單位必須先將資料匯出，以 Excel 進行整理與格式轉換，再人工匯入目標系統。不僅需要重複處理資料，也容易因欄位格式、資料內容或操作時間不同而發生異常。

02 · THE CHALLENGE

需求與多方認知持續變動，架構不能綁死

本案涉及多套異質系統，各系統的資料結構、交換格式、執行時間與負責單位均不相同。專案進行期間，需求、資料定義及不同單位對流程的認知也持續調整。

若直接為每兩套系統分別建立固定介接程式，後續需求改變時容易牽動多個介接點，也會提高測試與維護成本。

唯一不變的是改變。因此，設計重點不是把當下需求寫死，而是建立能持續調整資料來源、格式與排程的共通架構。

03 · IMPLEMENTATION

以中介資料庫建立共通交換與排程管理

核心成員主導需求分析、系統設計與跨單位協調，設計中介資料庫作為人資、ERP、簽核、人才發展及 BI 等異質系統之間的共通資料來源與交換層。

共通資料交換層

各系統不必直接彼此綁定，而是透過中介資料庫進行資料整理、轉換與交換，降低單一系統異動對其他介接流程的影響。

定時同步與格式轉換

  • 定時同步組織、人員等基礎資料及資料倉儲所需內容。
  • 依照薪資會計傳票及分錄需求，自動產生目標系統所需的上傳格式。
  • 整合多個資料來源，製作符合管理需求的綜合性客製報表。

異常檢查與電子郵件提醒

資料交換前先檢查來源內容與必要欄位。發現資料缺漏、格式不符或內容異常時，透過電子郵件通知相關人員確認，避免錯誤資料直接進入後續系統。

執行記錄與失敗重跑

自動化排程透過 SQL Server Agent 執行，並由 SQL 層記錄工作的執行時間、處理狀態與異常結果。介接工作執行失敗時，可依記錄確認問題並進行失敗重跑，不必重新處理整批資料。

04 · OUTCOME

從人工搬運資料，轉為可管理的自動交換流程

透過中介資料庫、SQL Server Agent 與自動化排程，逐步建立異質系統和既有人資系統之間的資料交換標準。

基礎資料、會計傳票與分析資料能依排程自動交換，降低 Excel 整理、格式轉換及人工匯入的需求；每項介接工作也保留執行記錄，並具備異常通知與失敗重跑能力。

更重要的是，整合架構保留面對需求變動的彈性。後續新增系統、資料來源或交換格式時，可以在既有基礎上繼續延伸，不必推翻原有介接流程。

05 · EXPERIENCE TO PRODUCT

從實務整合經驗延伸至 HCS API Agent

這類中介資料庫、T-SQL 排程、異常通知、執行記錄與失敗復原的實務經驗，成為後續發展 HCS API Agent 架構的重要基礎。

本案例並非使用現今的 HCS API Agent 產品，而是呈現核心成員如何從長期企業整合需求中，累積可重複應用的架構思維與交付經驗。
